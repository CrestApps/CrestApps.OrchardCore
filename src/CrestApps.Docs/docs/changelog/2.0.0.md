# Version 2.0.0 Release Notes

**Release date:** August 4, 2026

Version `2.0.0` is a major CrestApps.OrchardCore release. It moves the platform to **.NET 10** and the Orchard Core `3.0.0` preview line, and it expands CrestApps from a set of focused Orchard Core extensions into a broader modular platform for AI, content operations, omnichannel communication, phone-number intelligence, telephony, reporting, recipes, and administration.

This release note focuses on changes that matter when adopting or upgrading to `2.0.0`. Small internal cleanups and low-impact fixes are intentionally omitted so the upgrade path and new capabilities are easier to follow.

## At a glance

| Area | What changed |
| --- | --- |
| Platform | Requires `.NET 10`, targets `net10.0`, and restores against the Orchard Core `3.0.0-preview` package line. |
| AI | Adds a larger AI platform with provider connections, typed deployments, chat, chat interactions, Copilot, Claude, agents, tools, prompt templates, A2A, MCP, documents, memory, and data sources. |
| Retrieval | Moves from provider-bound retrieval patterns to provider-agnostic **AI Data Sources**, **AI Documents**, and **AI Memory**. |
| Omnichannel | Adds the Omnichannel platform, management UI, subject flows, SMS support, DNC registry integration, and contact import/export improvements. |
| Phone intelligence | Adds phone fields, phone-number verification, provider integrations, verification queueing, reports, and automatic omnichannel contact verification. |
| Telephony | Adds a provider-agnostic soft phone, SignalR telephony hub, call history, click-to-dial support, and a DialPad provider. |
| Data operations | Adds Content Transfer for CSV and Excel import/export, large chunked uploads, recipe/schema improvements, reports, and reusable date-range filtering. |
| Documentation | The Docusaurus documentation site under `src/CrestApps.Docs` is the primary product documentation. |

## Before you upgrade

`2.0.0` is a major release. Back up every tenant database and review enabled features, package references, custom modules, app settings, recipes, and deployment plans before starting the upgraded application.

The most important platform-level changes are:

| Area | v1.x | 2.0.0 |
| --- | --- | --- |
| .NET SDK | `8.0.100` | `10.0.100` |
| Target frameworks | `net8.0;net9.0` | `net10.0` |
| Orchard Core | `2.1.x` line | `3.0.0-preview` line |
| Package feeds | NuGet | NuGet, Orchard Core preview, and CrestApps Core preview feeds |
| Shared runtime | Mostly repository-local projects | Shared `CrestApps.Core.*` packages plus Orchard integration modules |
| AI deployments | Provider-specific or name-based selectors | First-class typed deployment records with purposes |
| Retrieval | Mostly Azure OpenAI BYOD-oriented | Provider-agnostic data sources, documents, and memory |
| Documentation | README-oriented | Docusaurus documentation |

## Breaking changes and required review

Review these items before upgrading production tenants.

| Area | What you need to review |
| --- | --- |
| Runtime | Install the .NET 10 SDK, move application projects to `net10.0`, and use the updated package feeds from the repository `NuGet.config`. |
| Custom code | Rebuild custom modules against the new package layout. Several reusable services moved into shared `CrestApps.Core.*` packages. |
| Async interfaces | Public async interfaces that perform longer-running or cancellable work now commonly accept `CancellationToken cancellationToken = default`. Custom implementations may need signature updates. |
| AI deployments | Older deployment selectors are replaced by deployment records. Review provider connections, deployments, deployment defaults, profiles, templates, chat interactions, and any custom code that stores deployment names. |
| AI deployment purpose | Deployment records now use **Purpose** instead of the older **Type** concept. The platform also adds a **Vision** purpose. |
| AI configuration | The preferred configuration path is now `OrchardCore:CrestApps:AI`. Older `CrestApps_AI` paths still work but are deprecated and log warnings. |
| Omnichannel Management | Workflow-driven and campaign-action-driven behavior moved to **Subject Flows** and **Subject Actions**. The old workflow activity integration was removed. |
| Subject configuration | Subject flow configuration now lives on `OmnichannelSubjectPart` content-type part settings and travels through standard content-definition deployment. The old `SubjectFlowSettings` catalog, recipe step, and deployment step were removed. |
| Disposition policy | Subjects now require a disposition by default. Clear the option on subjects that should complete without an outcome, such as one-way notifications. |
| Content Transfer | `ContentItemVersionId` is export-only for versionable content types and is ignored on import. Existing canceled imports migrate to the new paused state. |
| Telephony administration | Telephony provider settings are owned by the Telephony Administration feature, while the core feature can be enabled without the admin surface. |

## Major new features

### Artificial Intelligence platform

`2.0.0` substantially expands the AI platform and makes AI configuration more consistent across providers and experiences.

Key additions include:

- **Provider connections and typed deployments** that separate provider credentials from model deployments and centralize default deployment selection.
- **Deployment purposes**, including chat, utility, embedding, speech, text-to-speech, and vision scenarios.
- **AI Profiles and AI Profile Templates** for reusable tenant-level AI behavior.
- **Prompt Templates** for reusable system prompts and generated prompt profiles.
- **AI Agents and orchestration** so tools, retrieval, templates, agents, and external integrations can participate in coordinated flows.
- **AI Tool Instances**, including configurable HTTP API tool instances that administrators can attach to profiles, templates, interactions, and post-session processing.
- **Response Handlers** for extensible chat handling, live-agent handoff, deferred processing, and hybrid AI/human support scenarios.

See [Artificial Intelligence Suite](../ai/index.md), [AI Agent](../ai/agent.md), [AI Tool Management](../ai/tools.md), [AI Tool Instances](../ai/tool-instances.md), [AI Prompt Templates](../ai/prompt-templates.md), [AI Profile Templates](../ai/profile-templates.md), and [Response Handlers](../ai/response-handlers.md).

### AI Chat, Chat Interactions, Copilot, and Claude

The AI chat experience now supports richer admin and frontend scenarios, deployment-aware execution, citation rendering, anti-spam controls, session analytics, dark-mode-friendly UI, and more reliable client-side initialization.

New or expanded chat capabilities include:

- **AI Chat Interactions** for ad-hoc completions that do not require a predefined AI profile.
- A richer **AI Completion using Direct Config** workflow task with content, knowledge, and capability tabs.
- **GitHub Copilot-style chat integration** for Orchard Core through the Copilot module.
- **Claude integration** with provider-specific settings and deployment selection.
- Citation rendering for `[doc:N]` markers when references can be resolved.
- Profile-level anti-spam throttle overrides for profile templates and profiles.
- Deployment-aware speech controls that appear only when the required speech deployments are available.

See [AI Chat](../ai/chat.md), [AI Chat Analytics](../ai/chat-analytics.md), [AI Chat Interactions](../ai/chat-interactions.md), [AI Chat Copilot Integration](../ai/copilot.md), and [Claude](../ai/claude.md).

### Retrieval, documents, and memory

The retrieval architecture is now provider-agnostic. Instead of tying knowledge features to one provider-specific BYOD flow, `2.0.0` introduces reusable modules for data sources, uploaded documents, and persistent memory.

Important capabilities include:

- **AI Data Sources** for mapping tenant content or external sources into knowledge-base indexes.
- Built-in AI data-source source types for **Search Index Profile**, **Azure AI Search**, **Elasticsearch**, and **PostgreSQL**.
- **AI Documents** for upload, parsing, chunking, indexing, and retrieval.
- Document integrations for PDF, OpenXML, Azure Blob Storage, Azure AI Search, and Elasticsearch.
- **AI Memory** for persistent assistant memory backed by provider-specific indexing strategies.
- Migration and normalization paths for older AI data-source, document, memory, and deployment records.

See [AI Data Sources](../ai/data-sources/index.md), [AI Documents](../ai/documents/index.md), [PDF support](../ai/documents/pdf.md), [OpenXML support](../ai/documents/openxml.md), [Azure Blob Storage](../ai/documents/azure-blob-storage.md), and [AI Memory](../ai/memory.md).

### A2A and MCP

`2.0.0` adds broader agent and integration protocols.

- **A2A support** lets Orchard-hosted AI solutions participate in agent-to-agent workflows.
- **MCP server and client support** lets Orchard Core expose resources to MCP clients and consume external MCP servers.
- FTP and SFTP MCP resource modules extend the resource surface.
- MCP and A2A host authentication default to `OpenId` when no authentication type is configured, so anonymous access must be selected explicitly.
- API key comparisons and shared OAuth editor behavior were hardened for these protocol integrations.

See [A2A](../ai/a2a/index.md), [Model Context Protocol](../ai/mcp/index.md), [MCP Server](../ai/mcp/server.md), [MCP Client Integration](../ai/mcp/client.md), [FTP MCP resources](../ai/mcp/ftp.md), and [SFTP MCP resources](../ai/mcp/sftp.md).

### Content Access Control and Content Fields

`2.0.0` adds content-level access and reusable phone-number content fields.

- **Content Access Control** lets administrators restrict content items by attaching `RolePickerPart` and enabling role-based enforcement for the content type.
- **PhoneField** stores phone numbers in E.164 format with country code and national number metadata.
- The phone editor uses country-aware input and validates values through the shared phone-number service.
- Omnichannel contact data migrates from older text-based phone storage into the normalized phone field model.

See [Content Access Control](../modules/content-access-control.md) and [Content Fields](../modules/content-fields.md).

### Content Transfer

The new **Content Transfer** modules provide reusable import and export flows for Orchard content.

Highlights include:

- CSV import/export in the base feature.
- Optional Excel workbook support through `CrestApps.OrchardCore.ContentTransfer.OpenXml`.
- Bulk import and export settings per content type.
- Large-file import support through content-transfer-specific chunked uploads.
- Import states for pending, paused, and deleting work.
- A **Publish imported content** option that lets administrators save imported items as drafts or publish them immediately.
- Safer update behavior that applies imported values to a new latest version before saving or publishing.
- Omnichannel contact import/export support for phone, email, communication preferences, DNC flags, and time zones.

The chunked-upload settings live under `OrchardCore:CrestApps:ContentTransfer` and allow import limits to be raised without weakening the global media library upload limits.

See [Content Transfer](../modules/content-transfer.md).

### DNC Registry

`2.0.0` expands Do Not Call support with provider-specific configuration and a local registry.

Key improvements include:

- Dedicated settings pages under **Settings -> DNC Registries**.
- Protected storage for provider API keys.
- Provider pages that appear only when the matching feature is enabled.
- A shared DNC abstraction package for provider implementations.
- A **Local Do Not Call Registry** feature for uploading country-specific CSV phone lists.
- Background processing, progress reporting, and row-level validation for local DNC uploads.
- E.164 normalization through the shared phone-number service.

See [DNC Registry](../modules/dnc-registry.md).

### Omnichannel

The new Omnichannel platform brings contact management, activity management, campaign structure, subject flows, SMS, Event Grid integration, and import/export support into CrestApps.OrchardCore.

Important capabilities include:

- `OmnichannelContactPart` with contact methods, communication preferences, time-zone support, and normalized phone storage.
- Subject flows and subject actions under **Interaction Center -> Subject Flows**.
- Manual and automatic activity inventory loading.
- A **Manage Activities** page with contact/activity filters, urgency indicators, page-size selection, and bulk actions.
- Activity completion rules driven by subject disposition policy.
- Standard Orchard Core deployment and recipe steps for dispositions, channel endpoints, campaign groups, campaigns, and subject actions.
- SMS channel support, including improved webhook handling.
- Azure Event Grid webhook authentication with metadata-backed bearer token validation and constant-time SAS key comparison.

The largest conceptual change is that subject behavior now belongs to the subject content type. Configure subject direction, channel, interaction type, AI behavior, required disposition, and related settings on `OmnichannelSubjectPart` part settings.

See [Omnichannel Communications](../omnichannel/index.md), [Omnichannel Management](../omnichannel/management.md), [SMS](../omnichannel/sms.md), and [Event Grid](../omnichannel/event-grid.md).

### Phone Number Verifications

`2.0.0` introduces a provider-agnostic phone-number verification framework.

The core framework provides:

- `PhoneNumberVerificationPart` for storing submitted and normalized phone data, provider result details, verification status, attempt metadata, and revalidation timestamps.
- Automatic verification of omnichannel contact phone numbers after create or update.
- A throttled background processor for pending and expired verification work.
- Retry limits, failed-attempt tracking, and a **Needs attention** state for records that require administrator review.
- A **Phone Verifications Queue** dashboard under **Tools** for monitoring, searching, sorting, and retrying records.
- A **Phone Number Verifications** report under **Reports**.

Built-in providers include:

| Provider | Notes |
| --- | --- |
| AbstractAPI | Uses the Phone Validation service and stores API keys as protected values. |
| Twilio | Uses Twilio Lookup v2 with support for optional lookup data packages. |
| Veriphone | Uses the Veriphone `/v2/verify` endpoint with bearer-token authentication. |

See [Phone Number Verifications](../modules/phone-number-verifications.md), [AbstractAPI](../modules/phone-number-verifications-abstractapi.md), [Twilio](../modules/phone-number-verifications-twilio.md), and [Veriphone](../modules/phone-number-verifications-veriphone.md).

### Reports and shared Resources

The new **Reports** module provides a shared admin reports area with reusable filters, metrics, tables, charts, permissions, and exports.

Included capabilities:

- CSV exports from the base Reports feature.
- Optional Excel exports through `CrestApps.OrchardCore.Reports.OpenXml`.
- Shared report abstractions in `CrestApps.OrchardCore.Reports.Abstractions`.
- Omnichannel reports for activity summaries, campaign performance, and disposition breakdowns.
- Phone-number verification reports for verification health and provider usage.

The **Resources** module adds a reusable `DateRangePicker` view component used by reports and omnichannel activity filters. It supports relative day presets, calendar periods, rolling months, custom ranges, and on-or-before/on-or-after bounds.

See [Reports](../modules/reports.md) and [Resources](../modules/resources.md#date-range-picker).

### Recipes and workflow activity schemas

The Recipes module is significantly more capable in `2.0.0`.

Highlights include:

- Richer JSON schemas for content, content definitions, settings, roles, media, templates, layers, placements, workflows, AI profiles, AI data sources, MCP resources, A2A connections, and more.
- Tenant-aware examples for dynamic values such as content types, roles, provider names, deployment names, profile template sources, workflow activities, and time zones.
- Built-in schema contributors for common Orchard Core fields and CrestApps parts.
- Content-item schema composition through `IContentItemSchemaService`.
- A dedicated workflow activity schema model that describes activity properties, expression syntax, required fields, outcomes, and structural rules.
- Extensibility points for modules that need to describe custom content parts, fields, content schemas, or workflow activities.
- A Recipe Schema Exporter utility under `utilities\`.

See [Recipes](../modules/recipes.md) and [Workflow Activity Schemas](../modules/workflow-activity-schemas.md).

### SignalR

SignalR hubs can now opt in to Orchard Core `Api` authentication through `AllowApiTokenAuthenticationAttribute`.

This allows headless clients, single page applications, mobile apps, and service-to-service callers to connect to CrestApps hubs with an OpenID access token in an `Authorization: Bearer` header or through the standard SignalR `access_token` query string parameter. Cookie-authenticated and anonymous hub behavior remains unchanged unless a hub opts in.

`AIChatHub`, `ChatInteractionHub`, and `TelephonyHub` opt in by default.

See [SignalR](../modules/signalr.md#authenticating-with-access-tokens).

### Telephony and DialPad

The new Telephony modules provide a provider-agnostic soft phone for Orchard Core.

Core capabilities include:

- A floating soft phone widget that can appear in the admin dashboard, the frontend, or both.
- A SignalR `TelephonyHub` for dial, answer, reject, hang up, hold, mute, transfer, merge, DTMF, and related call actions.
- Provider-agnostic telephony abstractions for call control, call state, inbound calls, directory, audio, recording media, authentication, and provider capabilities.
- Per-user provider authentication support for OAuth-based providers.
- Recent call history, active-call state, missed-call highlighting, and persisted telephony interactions.
- Click-to-dial support from phone field displays and editors when the soft phone is present.
- A separate Telephony Administration feature for provider settings and navigation.

The new **DialPad** provider integrates DialPad through its REST API. It supports production and sandbox environments, API key authentication, OAuth 2.0 with PKCE, offline access, provider-side token revocation on disconnect, protected secret storage, and a fixed DialPad API endpoint.

See [Telephony](../telephony/index.md) and [DialPad](../telephony/dialpad.md).

### Time Zones

The new **Time Zones** module manages friendly named time-zone maps through admin UI, recipes, deployment plans, and a seed recipe.

Omnichannel time-zone selectors use this provider instead of Orchard Core's raw IANA list, which lets administrators present meaningful time-zone choices to operators and imported contact workflows.

See [Time Zones](../modules/time-zones.md).

### Platform, packaging, and tooling

`2.0.0` also includes several platform-level improvements:

- Centralized NuGet package metadata and package tags.
- Updated package feeds for Orchard Core previews and CrestApps Core preview packages.
- Patched npm transitive dependencies through workspace overrides.
- A more reliable Gulp rebuild pipeline that waits for CSS and JavaScript output streams before completing.
- Rebuilt bundled scripts and styles for Orchard-hosted chat, admin lists, and widget surfaces.
- Docusaurus documentation as the canonical product documentation.

## Upgrade checklist

Use this sequence when upgrading a tenant or solution from `v1.x`.

### 1. Prepare the environment

1. Back up every tenant database.
2. Install the .NET 10 SDK.
3. Update application projects to `net10.0`.
4. Adopt the updated package feeds from the repository `NuGet.config`.
5. Update package references to the `2.0.0` line.

### 2. Review custom modules and integrations

Check custom code for moved namespaces, new package references, interface signature changes, legacy AI deployment selectors, old feature IDs, and provider-specific retrieval assumptions.

Pay special attention to custom implementations of async interfaces and custom modules that referenced older repository-local core projects.

### 3. Start the upgraded tenant and let migrations run

Start the application once and allow Orchard Core and CrestApps data migrations to complete.

After startup, review migration-sensitive areas:

- AI provider connections
- AI deployments and default deployment settings
- AI profiles, profile templates, and prompt templates
- Chat sessions and chat interactions
- AI data sources, documents, and memory indexes
- Omnichannel contacts, subject settings, and activity data
- Phone-number verification records
- Content Transfer import/export settings
- Time-zone maps

### 4. Reconfigure AI where needed

Open the AI administration screens and confirm:

1. Provider connections are present and usable.
2. Deployments have the expected purposes.
3. Default deployments are selected for chat, utility, embedding, speech, text-to-speech, and vision scenarios as needed.
4. Profiles and profile templates use the correct deployments, tools, tool instances, data sources, documents, MCP resources, and A2A connections.
5. Chat widgets, admin chat, chat interactions, and workflow AI tasks use the intended profile or direct configuration.

### 5. Reconfigure Omnichannel subject flows

For each subject content type:

1. Open the content type editor.
2. Review `OmnichannelSubjectPart` settings.
3. Confirm direction, interaction type, channel, required disposition, campaign fallback, channel endpoint, and AI configuration.
4. Review subject actions under **Interaction Center -> Subject Flows**.
5. Recreate workflow-driven or campaign-action-driven behavior as subject actions where needed.

### 6. Validate data operations

Validate the operational flows your tenant uses:

- Content import/export
- Large file import
- Omnichannel contact import/export
- DNC registry uploads and lookups
- Phone-number verification queue and reports
- Telephony soft phone and provider authentication
- Recipes and deployment plan exports
- Reports and date-range filters

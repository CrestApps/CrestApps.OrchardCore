# Version 3.0.0 Release Notes

This page highlights the changes in the `3.0.0` line.

## Breaking Changes

### SignalR

- The Redis SignalR backplane has moved out of the `CrestApps.OrchardCore.SignalR` module into its own module and NuGet package (`CrestApps.OrchardCore.SignalR.Redis`) so the base module no longer carries any Redis dependency. The feature ID is unchanged, but the code that backs it now lives in a separate package. If you enable the Redis backplane feature, you must add a package reference to `CrestApps.OrchardCore.SignalR.Redis`; the package references the base SignalR module automatically. Tenants that do not use the Redis backplane no longer pull in the Redis packages.

- The shared SignalR primitives `SignalRConstants`, `TenantSignalRGroupName`, and `HubConnectionWork` have moved into a new `CrestApps.OrchardCore.SignalR.Core` support package, and `TenantSignalRGroupName` and `HubConnectionWork` are now in the `CrestApps.OrchardCore.SignalR.Core` namespace (previously `CrestApps.OrchardCore.SignalR`). The base SignalR module and both backplane modules reference this package automatically, so most consumers only need to update the `using CrestApps.OrchardCore.SignalR.Core;` directive when they reference these types directly.

### Resource Module

- The `crestapps-bootstrap-select` style and script have been removed from the `Resource` module. Instead you should use the `bootstrap-select` style and script which are registered by Orchard Core.

### Omnichannel Management

- The `OmnichannelContentTypeProvider` service is now registered as **scoped** instead of **singleton**, and its public query methods are now asynchronous and return `ValueTask`. Update any callers accordingly:

  | Old (synchronous) | New (asynchronous) |
  |---|---|
  | `bool IsSubjectContentType(string contentType)` | `ValueTask<bool> IsSubjectContentTypeAsync(string contentType)` |
  | `bool IsContactContentType(string contentType)` | `ValueTask<bool> IsContactContentTypeAsync(string contentType)` |
  | `IReadOnlyCollection<string> GetSubjectContentTypes()` | `ValueTask<IReadOnlyCollection<string>> GetSubjectContentTypesAsync()` |
  | `IReadOnlyCollection<string> GetContactContentType()` | `ValueTask<IReadOnlyCollection<string>> GetContactContentTypesAsync()` |

  The provider now caches its membership sets in a per-tenant `IMemoryCache`, so the initialization is handled internally and callers should simply `await` the query methods. `OmnichannelContentTypeProvider` no longer implements `IContentDefinitionEventHandler`; cache invalidation on content definition changes is handled by a separate internal handler.

## Change Logs

### Omnichannel Management

#### Contacts menu in the Interaction Center

The **Interaction Center** admin menu now includes a **Contacts** item. It opens the standard Orchard Core content list restricted to the Omnichannel contact content types by passing every content type that attaches `OmnichannelContactPart` as a comma-separated `contentTypeId` to the content `List` action. The contact types come from the cached content-type provider, so the menu stays in sync as the part is attached or detached. The item is guarded by the **List content** permission.

See [Omnichannel Management](../omnichannel/management) for details.

-----

### AI Documents

#### File upload security scanning through Orchard Core

The **AI Documents** module now routes every uploaded file through Orchard Core's shared [`FileCreationService`](https://docs.orchardcore.net/en/latest/reference/core/file-upload-security/) pre-storage pipeline before the file is stored or processed.

Highlights:

- Uploads from chat interactions, profiles, chat sessions, and widgets are scanned before storage.
- Enabling the `OrchardCore.Antivirus` feature adds **ClamAV** virus scanning to all AI document uploads with no additional code.
- Rejections are fail-closed and logged at `Warning` level.

See [AI Documents](../ai/documents) for details.

-----

### SignalR

#### Redis backplane extracted into its own module

The SignalR Redis backplane now ships as a dedicated module and NuGet package, `CrestApps.OrchardCore.SignalR.Redis`, so the base **SignalR** module (`CrestApps.OrchardCore.SignalR`) no longer carries any Redis dependency. The feature ID is unchanged, and the package depends on both the base SignalR module and `OrchardCore.Redis`. Tenants that already enabled the Redis backplane feature keep working after installing the package; tenants that do not need scale-out avoid pulling in the Redis packages.

See [SignalR](../modules/signalr) for details.

#### Azure SignalR Service backplane

A new **SignalR Azure Backplane** feature (`CrestApps.OrchardCore.SignalR.Azure`) routes SignalR traffic through the [Azure SignalR Service](https://learn.microsoft.com/azure/azure-signalr/signalr-overview), offering a managed scale-out option alongside the Redis backplane. It ships as its own module and NuGet package (`CrestApps.OrchardCore.SignalR.Azure`), which references the base SignalR module automatically, so the base module carries no Azure dependency. Add the package, enable the feature, and supply the connection string under `CrestApps:SignalR:Azure:ConnectionString`. When the feature is enabled without a connection string, the backplane is skipped and a warning is logged rather than failing tenant startup. Enable only one backplane (Redis or Azure) per tenant.

See [SignalR](../modules/signalr) for details.

#### Verified multi-tenant and distributed hub isolation

The **SignalR** module's cross-tenant isolation is now backed by a dedicated test suite that treats tenant separation as a security guarantee rather than an assumption.

Highlights:

- The Redis backplane channel prefix is proven to combine `InstancePrefix`, the immutable Orchard shell name, and a `:SignalR` suffix, so two nodes serving the same tenant share one channel namespace while different tenants (and different deployments that reuse a shell name) never share hub control channels.
- The backplane clones the shared Orchard Redis connection options instead of mutating them, so configuring the SignalR connection can never corrupt Orchard's shared cache, bus, or lock connection.
- The Redis backplane only wires up when `OrchardCore.Redis` services are present, so enabling the feature without Redis is a safe no-op.
- `TenantSignalRGroupName` uses length-prefixed encoding, so equal user, queue, or supervisor identifiers in different shells stay isolated and a crafted group name cannot spoof another tenant's destination.

See [SignalR](../modules/signalr) for details.

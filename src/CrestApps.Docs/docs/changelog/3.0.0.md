# Version 3.0.0 Release Notes

This page highlights the changes in the `3.0.0` line.

## Breaking Changes

### Resource Module

- The `crestapps-bootstrap-select` style and script have been removed from the `Resource` module. Instead you should use the `bootstrap-select` style and script which are registered by Orchard Core.

### Omnichannel Management

- The `OmnichannelContentTypeProvider` service is now registered as **scoped** instead of **singleton**, and its public query methods are now asynchronous and return `ValueTask`. Update any callers accordingly:

  | Old (synchronous) | New (asynchronous) |
  |---|---|
  | `bool IsSubjectContentType(string contentType)` | `ValueTask<bool> IsSubjectContentTypeAsync(string contentType)` |
  | `bool IsContactContentType(string contentType)` | `ValueTask<bool> IsContactContentTypeAsync(string contentType)` |
  | `IReadOnlyCollection<string> GetSubjectContentTypes()` | `ValueTask<IReadOnlyCollection<string>> GetSubjectContentTypesAsync()` |
  | `IReadOnlyCollection<string> GetContactContentType()` | `ValueTask<IReadOnlyCollection<string>> GetContactContentTypesAsync()` |

  The provider now caches its membership sets in a per-tenant `IMemoryCache`, so the initialization is handled internally and callers should simply `await` the query methods. `OmnichannelContentTypeProvider` no longer implements `IContentDefinitionEventHandler`; cache invalidation on content definition changes is handled by a separate internal handler.

## Change Logs

### Omnichannel Management

#### Contacts menu in the Interaction Center

The **Interaction Center** admin menu now includes a **Contacts** item. It opens the standard Orchard Core content list restricted to the Omnichannel contact content types by passing every content type that attaches `OmnichannelContactPart` as a comma-separated `contentTypeId` to the content `List` action. The contact types come from the cached content-type provider, so the menu stays in sync as the part is attached or detached. The item is guarded by the **List content** permission.

See [Omnichannel Management](../omnichannel/management) for details.

-----

### AI Documents

#### File upload security scanning through Orchard Core

The **AI Documents** module now routes every uploaded file through Orchard Core's shared [`FileCreationService`](https://docs.orchardcore.net/en/latest/reference/core/file-upload-security/) pre-storage pipeline before the file is stored or processed.

Highlights:

- Uploads from chat interactions, profiles, chat sessions, and widgets are scanned before storage.
- Enabling the `OrchardCore.Antivirus` feature adds **ClamAV** virus scanning to all AI document uploads with no additional code.
- Rejections are fail-closed and logged at `Warning` level.

See [AI Documents](../ai/documents) for details.

### Recipes

#### Extensible rule condition schemas for the Layers recipe step

The `Layers` recipe step now produces a fully described JSON schema for each layer's `LayerRule`, including every rule condition and every condition operator. When the `OrchardCore.Layers` feature is enabled, all built-in conditions and operators from `OrchardCore.Rules` are described out of the box, and the schema recurses through condition groups.

Highlights:

- Every condition (`UrlCondition`, `ContentTypeCondition`, `RoleCondition`, `CultureCondition`, `BooleanCondition`, `HomepageCondition`, `JavascriptCondition`, `IsAnonymousCondition`, `IsAuthenticatedCondition`, `AllConditionGroup`, `AnyConditionGroup`) and every string operator is described with its members and their descriptions.
- New extension points `IRuleConditionSchemaDefinition` and `IRuleConditionOperatorSchemaDefinition`, with the base classes `RuleConditionSchemaDefinitionBase`, `OperandConditionSchemaDefinitionBase`, `ConditionGroupSchemaDefinitionBase` and `RuleConditionOperatorSchemaDefinitionBase`, let any module contribute custom conditions and operators through `AddRuleConditionSchema<T>()` and `AddRuleConditionOperatorSchema<T>()`.
- The `RecipeSchemaExporter` utility now emits the composed `Layers` schema, so the generated AgentSkills reference schemas describe layer rules.

See [Rule Condition Schemas](../modules/rule-condition-schemas.md) for details.

When the `OrchardCore.Sitemaps` feature is enabled, all built-in sources are described out of the box, and both the sitemap object and every source are described with their polymorphic `$type` discriminators.

Highlights:

- Every source (`ContentTypesSitemapSource`, `CustomPathSitemapSource`, `SitemapIndexSource`) is described with its members and their descriptions, and the sitemap object distinguishes a standard sitemap from a sitemap index.
- New extension point `ISitemapSourceSchemaDefinition`, with the base class `SitemapSourceSchemaDefinitionBase`, lets any module contribute custom sources through `AddSitemapSourceSchema<T>()`.

#### Extensible deployment step schemas for the deployment recipe step

The `deployment` recipe step now produces a fully described JSON schema for each plan and its `Steps` array. When the `OrchardCore.Deployment` feature is enabled, every deployment step available on the tenant is offered as a `Type` suggestion, and each step's `Step` payload is described.

Highlights:

- Every built-in deployment step that carries configurable data, across content, content definitions, media, templates, queries, settings, data localization and the Lucene, Elasticsearch, Azure AI Search and index profile providers, is described with its members and their descriptions.
- New extension point `IDeploymentStepSchemaDefinition`, with the base class `DeploymentStepSchemaDefinitionBase`, lets any module contribute custom deployment steps through `AddDeploymentStepSchema<T>()`.
- The composition service only describes steps whose factory is present on the tenant, so schemas stay aligned with the enabled features while unknown steps still validate.
- The `RecipeSchemaExporter` utility now emits the composed `deployment` schema, so the generated AgentSkills reference schemas describe deployment steps.

See [Deployment Step Schemas](../modules/deployment-step-schemas.md) for details.

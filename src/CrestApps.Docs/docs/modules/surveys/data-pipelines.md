With Data Pipelines Core on, the **Surveys** data source (`Surveys`) offers these data sets to pipelines and the Report Builder. Data set and field names never change once shipped.

| Data set | Rows | Fields |
| --- | --- | --- |
| `Surveys` | One per survey | `Id`, `Name`, `Title`, `Kind`, `Status`, `Owner`, `PublishedVersion`, `Created`, `Modified` |
| `SurveyVersions` | One per published version | `Id`, `SurveyId`, `Number`, `PublishedUtc`, `PublishedBy`, `Notes` |
| `SurveyQuestions` | One per question per version | `SurveyId`, `VersionNumber`, `QuestionId`, `Name`, `ControlType`, `Title`, `Page`, `Position`, `Points`, `Category` |
| `SurveyResponses` | One per response | `Id`, `Number`, `SurveyId`, `SurveyName`, `VersionNumber`, `Status`, `Grading`, `Respondent`, `UserName`, `ContextKind`, `ContextId`, `Collector`, `Attempt`, `StartedUtc`, `CompletedUtc`, `DurationSeconds`, `Score`, `MaxScore`, `Percent`, `Passed`, `Ending`, `IsTest`, `ModifiedUtc`, plus the fields of every `ISurveyResponseFieldProvider` |
| `SurveyAnswers` | One per answer value of a completed response | `ResponseId`, `SurveyId`, `VersionNumber`, `QuestionId`, `QuestionName`, `RowId`, `ChoiceId`, `ChoiceValue`, `ChoiceText`, `NumberValue`, `DateValue`, `TextValue`, `Score`, `MaxPoints`, `CompletedUtc` |
| `SurveyCategoryScores` | One per score category of each completed response | `ResponseId`, `SurveyId`, `Category`, `Score` |
| `SurveyPageVisits` | One per page visit | `ResponseId`, `SurveyId`, `PageName`, `EnteredUtc`, `LeftUtc`, `Seconds` |
| `SurveyInvitations` | One per invitation (Invitations feature) | `Id`, `SurveyId`, `CollectorId`, `Recipient`, `Status`, `SentUtc`, `Reminders`, `ResponseId` |
| `SurveyResponses_{surveyName}` | One per response of a published survey | Response fields (`Id`, `Number`, `VersionNumber`, `Status`, `StartedUtc`, `CompletedUtc`, `Score`, `Percent`, `Passed`, `ContextKind`, `ContextId`, `UserId`, `Respondent`) and a column per question export column of every version, joined by question id and named after the newest version |

`SurveyResponses` reads by its modified time, so incremental pipeline runs only read what changed. The wide `SurveyResponses_{surveyName}` data sets are listed at run time, one per published survey: use them for "export my survey to Excel every Monday".

A person reads only the surveys whose responses they may view, and sees who responded on the identified ones ([who responded](./results-and-reports.md#who-responded)): identity fields (respondent, user name, user id, invitation recipient and response) are always empty for anonymous surveys. The wide data set also has a `Respondent` field with the display name (*Guest*, *Deleted user*, or *Anonymous* on an anonymous survey).

Rows of an anonymous survey follow the small-group rule of [Results and reports](./results-and-reports.md#anonymous-surveys): they wait until the completed responses reach the minimum group size, and each status waits until that many responses share it; a group that never does gives no rows. The check counts all of the survey's responses that pass the conditions Report Builder passes down other than dates (keys, equals and lists, text matches, number ranges), so a filter on an answer can't narrow a survey to one person, and a date range or a pipeline's watermark doesn't narrow the count to a few rows. Fields filled in after a response is read (the collector's name, the ending, a provider's field) are filled in before the count. Report Builder shares a read of these data sets between the views of a report only when their filters are the same, so a view or dashboard click with more filters is counted on its own filters. Filters Report Builder applies only after reading, and groupings in a view, can still narrow further, which is why anonymous rows also carry no context id, no attempt number and no response number (the `Number` field holds a keyed code), show their collector, version and context kind only when enough completed responses share all three (otherwise *Other* or blank), and show their times as the start of their day in the site's time zone (never the reader's own). An anonymous survey is read apart, a page at a time in the order of its response ids, and its rows are written one for one between the other rows, so a capped read or a preview shows some; each row has its own release moment: the latest of the end of the day it last changed on, the moment the minimum-th of the survey's counted completed responses ended theirs, the same moment within its status, and the same within its collector, version and context kind (or within *Other*). Only responses whose day has ended count toward a release. `ModifiedUtc` reads that moment, so a row held back until its group or status grew is released with a time past the last run, and an incremental read by `ModifiedUtc` never skips one. A condition on `ModifiedUtc` is read a day further back; other date ranges are widened to whole days. A condition on the survey itself (`SurveyId`, `SurveyName`) that rules an anonymous survey out skips it entirely; without conditions on the rows, the counts come from the index without reading a response.

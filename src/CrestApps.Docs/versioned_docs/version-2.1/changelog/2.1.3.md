# Version 2.1.3 Release Notes

**Release date:** September 5, 2026

Version `2.1.3` is a patch release for the .NET 10 and Orchard Core 3.0 line. It keeps the Orchard Core package range at `>= 3.0.0` and `< 3.1.0` and the CrestApps.Core package line at stable `1.2.0`. It contains a single fix: the OllamaSharp source generator build error reported in [issue 640](https://github.com/CrestApps/CrestApps.OrchardCore/issues/640).

:::danger
Do not use `2.1.3`. The fix below shipped with an MSBuild targets file that MSBuild cannot parse, which breaks every build that references the Ollama package. Update to [2.1.4](2.1.4), which carries the same fix with the targets file corrected.
:::

## Bug fixes

### OllamaSharp source generator build error (CS9057)

`OllamaSharp` `5.4.30` ships a Roslyn source generator (`OllamaSharp.SourceGenerators`) that is built against a newer C# compiler than earlier .NET 10 SDKs provide. On such an SDK the compiler reports `CS9057` and skips the generator. `CS9057` is a warning by default, but builds that treat warnings as errors fail on it. Because transitive analyzers and source generators reach consuming projects even when intermediate dependencies exclude analyzer assets, the failure surfaced in projects that reference the Ollama module rather than only in this repository.

This release addressed the problem in three places:

- `OllamaSharp` is now referenced centrally at `5.4.30` and pulled into the Ollama module with `ExcludeAssets="analyzers"`, so the generator does not run when the module itself is built.
- A build target removes the `OllamaSharp.SourceGenerators` analyzer before `CoreCompile` in this repository, because `ExcludeAssets` alone does not stop a generator that arrives transitively.
- The Ollama package ships a `buildTransitive` MSBuild targets file that adds `CS9057` to `NoWarn` in consuming projects. Suppressing the warning rather than removing the analyzer keeps the change non-breaking: on an older SDK the generator could not load anyway, and on a newer SDK no `CS9057` is emitted, so the suppression does nothing and OllamaSharp tool generation keeps working.

### Known issue: the buildTransitive targets file cannot be parsed

The `buildTransitive` targets file described above shipped with an XML comment containing a double hyphen, which is not allowed in XML. MSBuild failed to import the file in consuming projects with `MSB4024` ("An XML comment cannot contain '--'"), so every build that referenced the package failed regardless of SDK version. This was corrected the following day in [2.1.4](2.1.4).

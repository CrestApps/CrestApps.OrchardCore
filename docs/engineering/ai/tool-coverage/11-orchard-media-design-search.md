# Orchard Core: media, design, search and queries

Part of the [AI tool coverage plan](README.md). Nothing in this file is built yet. The design rules, the permission and approval model and the test plan that apply to every tool below are in [01-foundation.md](01-foundation.md) and [03-testing.md](03-testing.md); the final agent roster is in [02-agents.md](02-agents.md) and wins over the agent notes in this file.

Checkout inspected: `the Orchard Core repository` at commit `47c0c2c1` (main, 2026-11-16). State of this checkout that matters for the plan:

- Indexing is unified. `OrchardCore.Indexing` owns the only index list page (**Search → Indexes**, `IndexProfile` entities, one editor extended by provider display drivers). `OrchardCore.Lucene` and `OrchardCore.Elasticsearch` no longer have index list pages, only a "Run query" page each (Elasticsearch also has an "Index info" page). `OrchardCore.AzureAI` has no controller at all.
- The Media library API is a set of minimal-API endpoints (`api/media/*`, files in `OrchardCore.Media/Endpoints/Api/`) behind the `MediaApi` authorization policy (cookie by default, bearer optional). `Controllers/AdminController.cs` only serves the gallery page, the read-only Options page and `GetPermittedStorage`.
- There is no "upload from URL" or "create file from text" in the Media UI. The UI only uploads files from the admin's computer (chunked upload or TUS). Import from a URL and from Base64 exists only in the `media` recipe step. The two tools proposed below (`importMediaFromUrl`, `saveMediaTextFile`) are the chat equivalents of the upload button.
- No tool exists today for anything in this group (checked every `AddCoreAITool<` in `CrestApps.OrchardCore`). The only existing route is `importOrchardCoreRecipe` with the recipe steps listed per module.

Conventions used in the tables: every `deleteX`, `moveX`, `synchronizeX` and `rebuildX` tool accepts one or more identifiers (the UI has bulk actions for all of them). Permission is the Orchard permission `Name` string; the C# constant is given when the two differ.

## Media library — `OrchardCore.Media` (also affected by `OrchardCore.Media.Security`, `OrchardCore.Media.Slugify`, `OrchardCore.Media.Tus`, `OrchardCore.Media.SignalR`)

**What an admin can do in the UI:**

- **Media → Library** (`ManageMediaContent`): browse the folder tree, list files of a folder (optionally filtered by extension), see a file's size, type, date and public URL, upload files (chunked, or resumable with TUS), create a folder, delete a folder (recursive), delete one or several files, rename a file, move one or several files to another folder, copy a file. Folders cannot be renamed or moved (no endpoint).
- **Settings → Media → Options** (`ViewMediaOptions`): read-only page showing `MediaOptions` from configuration (allowed and restricted extensions, max file size, supported sizes, CDN base URL, cache days, assets path, users folder, chunk size, temp file lifetime).
- **Settings → Media → API** (`ManageMediaApiSettings`): choose cookie or bearer authentication for the Media API.
- Per-folder access: every endpoint checks `ManageMediaContent` plus `ManageMediaFolder` with the path as resource. `ManageMediaFolderAuthorizationHandler` maps the path to `ManageMediaContent` (normal folders), `ManageAttachedMediaFieldsFolder` (the `mediafields` folder), `ManageOwnMediaContent` (the user's own folder under `MediaOptions.AssetsUsersFolder`) or `ManageOthersMediaContent` (other users' folders). With Secure Media enabled it also requires `ViewMediaContent` on the path, and one dynamic permission `ViewMediaContent_{folder}` exists per top-level folder; those are granted in the Roles UI (another group).
- Attached media: a `MediaField` with the "Attached" editor uploads to a per-user temp folder and, on save, `AttachedMediaFieldFileService` moves the file to `mediafields/{ContentType}/{ContentItemId}/{hash}.ext`; the folder is deleted with the content item.

**Already covered:** content tools cover the value of a `MediaField` (`Paths`, `MediaTexts`) on a content item. Recipe steps usable through `importOrchardCoreRecipe`: `media` (`Files[]` with `TargetPath` and one of `Base64`, `SourcePath`, `SourceUrl`; always overwrites and always allows restricted extensions), `move-attached-media-fields` (moves library files referenced by "Attached" media fields into the content item folders; there is no UI for it). Nothing covers list, read, move, copy or delete.

**Settings groups:** `MediaApiSettings` / group `mediaApi` / permission `ManageMediaApiSettings` / secrets: none. Changing `AuthenticationScheme` calls `IShellReleaseManager.RequestRelease()` (tenant reload) and changes how the Media API authenticates, so the generic `updateSiteSettings` should treat this group as Security. `MediaTokenSettings.HashKey` is stored in site settings without any settings page (generated by `MediaTokenSettingsUpdater`); the generic settings tools must never list or return it.

**Implementation notes:**

- Services: `IMediaFileStore` (`GetDirectoryContentAsync`, `GetFilesAsync`, `GetDirectoriesAsync`, `GetFileInfoAsync`, `GetDirectoryInfoAsync`, `TryCreateDirectoryAsync`, `MoveFileAsync`, `CopyFileAsync`, `TryDeleteFileAsync`, `TryDeleteDirectoryAsync`, `GetFileStreamAsync`, `MapPathToPublicUrl`, `GetPermittedStorageAsync`), `FileCreationService` with the `CreateFileFromStreamAsync(fileCreationService, path, stream, length, contentType, cancellationToken)` extension (runs the `IFileEventHandler` pipeline; use it rather than the raw store method), `IMediaNameNormalizerService` (slugifies names when `OrchardCore.Media.Slugify` is on), `IOptions<MediaOptions>`, `IContentTypeProvider`, optional `IMediaFileStoreCache` (pre-cache after create or move on remote stores), `IAuthorizationService` with `MediaPermissions.ManageMediaFolder` and the path as resource. All of these are in `OrchardCore.Media.Abstractions`, `OrchardCore.Media.Core` or `OrchardCore.FileStorage.Abstractions`, so no module reference is needed for the file tools.
- Gap: all the business rules live in private static endpoint handlers (`Endpoints/Api/*.cs`) and cannot be called. The tools must repeat them: the permission pair, the special-folder checks (`AttachedMediaFieldFileService.MediaFieldsFolder` = `mediafields`, `MediaOptions.AssetsUsersFolder`), invalid folder name characters (`/`, `\`), "already exists" checks for file and folder, the extension check (`MediaOptions.AllowedFileExtensions`, plus `RestrictedFileExtensions` only with `UploadRestrictedMedia`; the `IsFileExtensionAllowed` helper is `internal`), and relative-path validation (`MediaFileStorePathHelper` is `internal`; reject rooted paths and `..` segments).
- Gap: `MediaDirectoryTreeCache` (singleton, public, but in the `OrchardCore.Media` module assembly) is only invalidated by the create-folder and delete-folder endpoints. A tool that creates or deletes a folder through `IMediaFileStore` without calling `Invalidate()` leaves the Media Library folder tree stale.
- `importMediaFromUrl` must not reuse the `media` recipe step: that step uses a plain `IHttpClientFactory.CreateClient()` with no host restriction, no size limit, `overwrite: true` and `hasAdditionalPermission: true`. The tool needs its own client: http/https only, block loopback, private and link-local addresses (server-side request forgery), enforce `MediaOptions.MaxFileSize`, timeout, extension taken from the target path and checked against the options.
- Default configuration (`MediaOptionsConfiguration`): allowed extensions are images, office documents, `.pdf`, `.csv`, audio and video; restricted are `.css`, `.js`, `.svg`. `.txt`, `.md`, `.json` and `.html` are not allowed unless configured. The default Editor role has `UploadRestrictedMedia` (flagged `isSecurityCritical` in code), which is why `saveMediaTextFile` is Security with approval: with defaults its main use is CSS, JavaScript and SVG served from the site origin.
- Moving or renaming breaks references: `MediaField.Paths` and HTML/Markdown bodies store the path as text and nothing tracks usage. The tool result should say so.
- Text extraction for `getMediaFile`: `IOptions<MediaFileIndexingOptions>.GetRegisteredMediaFileTextProvider(extension)` then `IMediaFileTextProvider.GetTextAsync(path, stream)`; providers exist for `.txt` and `.md` (`OrchardCore.Media.Indexing.Text`), `.pdf` (`OrchardCore.Media.Indexing.Pdf`), `.docx` and `.pptx` (`OrchardCore.Media.Indexing.OpenXML`). Cap the returned text.
- Attached media through content tools: `createOrUpdateContentItem` can only write library paths into `MediaField.Paths`; the attach workflow (`HandleFilesOnFieldUpdateAsync`) runs only in `MediaFieldDisplayDriver`. For an "Attached" field, follow with the `move-attached-media-fields` recipe step. The media tools should refuse to move or delete inside `mediafields` unless the user holds `ManageAttachedMediaFieldsFolder` (the handler already enforces it).
- Binary upload of a file the user attaches in the chat is not possible with these tools (see Open questions).

## Media profiles — `OrchardCore.Media`

**What an admin can do in the UI:**

- **Media → Profiles** (`ManageMediaProfiles`): list and search profiles, create, edit (including rename), delete one, bulk delete. A profile has name, hint, width, height (from `MediaOptions.SupportedSizes`, or a custom size when `UseTokenizedQueryString` is on), resize mode (Default, Max, Crop, Pad, BoxPad, Min, Stretch), format (Default, Gif, Jpg, Png, WebP), quality, background color and auto-orient.

**Already covered:** recipe step `MediaProfiles` (create or update; usable through `importOrchardCoreRecipe`). Listing and deleting are not covered.

| Tool | Kind | Approval | Permission | Description | Agent |
| --- | --- | --- | --- | --- | --- |
| `listMediaProfiles` | Read | no | `ManageMediaProfiles` | Lists the media profiles (named image resize presets) with their width, height, mode, format, quality and background color. Use it to find a profile name to use in templates, shortcodes or media fields. | MediaAgent |
| `saveMediaProfile` | Write | no | `ManageMediaProfiles` | Creates or updates a media profile (name, hint, width, height, resize mode, format, quality, background color, auto-orient) and can rename an existing one. Width and height must be one of the supported sizes unless tokenized query strings are enabled. | MediaAgent |

Rename in the UI is remove then update. The size validation (supported sizes, custom sizes only with `MediaOptions.UseTokenizedQueryString`, which defaults to true) lives in `MediaProfilesController` and must be repeated. Without a module reference, `saveMediaProfile` can be implemented with the `MediaProfiles` recipe step, but list and delete cannot.

## Templates — `OrchardCore.Templates`, `OrchardCore.AdminTemplates`

**What an admin can do in the UI:**

- **Design → Templates** (`ManageTemplates` and `ManageLiquidTemplates`): list and search templates, create, edit (name, description, Liquid content, rename), delete, bulk delete, live preview of an unsaved template against a content item URL (`PreviewController`).
- **Design → Admin Templates** (`ManageAdminTemplates` and `ManageLiquidTemplates`, feature `OrchardCore.AdminTemplates`): the same list and editor for templates applied in the admin.
- Shortcut links on the content type, content part and type-part editors that open the template editor with a suggested name: `{Stereotype}__{ContentType}` and `{Stereotype}_Summary__{ContentType}` (stereotype defaults to `Content`), `{PartName}` and `{PartName}_Summary`, `{ContentType}__{PartName}` and `{ContentType}_Summary__{PartName}`.

**Already covered:** recipe steps `Templates` and `AdminTemplates` (create or update; usable through `importOrchardCoreRecipe`). Listing, reading and deleting are not covered.

| Tool | Kind | Approval | Permission | Description | Agent |
| --- | --- | --- | --- | --- | --- |
| `listTemplates` | Read | no | `ManageLiquidTemplates` and `ManageTemplates` (site scope) or `ManageAdminTemplates` (admin scope) | Lists the Liquid shape templates stored in the database for the site or for the admin, with name and description and an optional name filter. Use it to see which shapes are already overridden before adding a template. | DesignAgent |
| `getTemplate` | Read | no | same as `listTemplates` | Returns the Liquid content and description of one site or admin template by name. | DesignAgent |
| `saveTemplate` | Security | yes | same as `listTemplates` | Creates or updates a Liquid template that overrides a shape for the site or the admin (for example `Content__BlogPost` or `Content_Summary__Article`), validating the Liquid syntax first; can rename an existing template. Templates run on every matching render and can output raw markup and read site data, so only save Liquid the user asked for and say which shape it replaces. | DesignAgent |
| `deleteTemplate` | Destructive | yes | same as `listTemplates` | Deletes one or more site or admin templates by name; the shape is rendered again by the theme's or module's own template. | DesignAgent |

**Implementation notes:**

- Services: `TemplatesManager` and `AdminTemplatesManager` (`GetTemplatesDocumentAsync`, `LoadTemplatesDocumentAsync`, `UpdateTemplateAsync(name, Template { Content, Description })`, `RemoveTemplateAsync`). Both, and the `Template` model, live in the `OrchardCore.Templates` module assembly. `Permissions.ManageTemplates` and `AdminTemplatesPermissions.ManageAdminTemplates` are also declared in the module assembly; `ManageLiquidTemplates` is in `OrchardCore.Liquid.Abstractions`.
- The controller checks two permissions for every action (`IsAuthorizedAsync`): `ManageLiquidTemplates` plus the scope permission. All three are flagged `isSecurityCritical` in code, and the default Editor role has `ManageTemplates` and `ManageLiquidTemplates`.
- `TemplateController` does not validate Liquid syntax on save (only name uniqueness and non-empty content). The tool should call `ILiquidTemplateManager.Validate(template, out errors)` and refuse invalid Liquid. Empty content is rejected in the UI with a hint to use Placements to hide a shape; keep that message.
- Rename is remove then update. The admin scope only has an effect when `OrchardCore.AdminTemplates` is enabled (`AdminTemplatesShapeBindingResolver` is registered by that feature), although the manager is registered by the base feature.
- Risk: a template is code. It can emit unencoded HTML and script to every visitor, call saved queries (including SQL queries) and read content regardless of the viewer's permissions, and a broken template for a layout-level shape can take the front end down; an admin template can break the admin UI itself, including the chat widget used to fix it.
- Not exposed: the live preview (`PreviewController.Render`, which renders a published content item with the unsaved template). See Open questions for a `renderLiquid` tool.

## Themes — `OrchardCore.Themes`

**What an admin can do in the UI:**

- **Design → Themes** (`ApplyTheme`): see all themes with the current site theme and current admin theme, **Make current** (sets the site or admin theme depending on the theme's `admin` manifest tag and enables its feature if needed), **Reset** the site theme or the admin theme, **Enable** or **Disable** a theme feature.

**Already covered:** recipe step `Themes` (`Site`, `Admin`; usable through `importOrchardCoreRecipe`) sets the current themes. Nothing else: the existing feature tools (`listSiteFeature`, `searchSiteFeature`, `getSiteFeature`, `enableSiteFeature`, `disableSiteFeature`) all filter themes out with `!feature.IsTheme()`, so they can neither show nor enable or disable a theme.

| Tool | Kind | Approval | Permission | Description | Agent |
| --- | --- | --- | --- | --- | --- |
| `listThemes` | Read | no | `ApplyTheme` | Lists the installed themes, saying for each whether it is a site or an admin theme and whether it is enabled, and which theme is currently used for the site and for the admin. Use it before changing the theme. | DesignAgent |
| `setTheme` | Write | no | `ApplyTheme` | Makes a theme the current site or admin theme (enabling it when needed), resets the current site or admin theme, or enables or disables a theme without making it current, depending on `action`. Making a theme current applies immediately to every visitor (site theme) or every admin user (admin theme); a theme that is current cannot be disabled. | DesignAgent |

**Implementation notes:** `ISiteThemeService` (`GetSiteThemeAsync`, `SetSiteThemeAsync`) is in the `OrchardCore.Themes` module assembly; `IAdminThemeService` is in `OrchardCore.Admin.Abstractions`; `IShellFeaturesManager` for the list and for enabling and disabling (`EnableFeaturesAsync` / `DisableFeaturesAsync` with `force: true`, as the controller does). The list logic (themes are features with `IsTheme()`, not always-enabled, not dependency-only, without the `hidden` manifest tag; admin theme = manifest tag `admin`) lives in `AdminController.Index` and must be extracted. For "make current" keep the controller's order: set the theme first and enable the feature last (its comment says this avoids using services of the shell that is disposed after the feature change). The four actions (`makeCurrent`, `reset`, `enable`, `disable`) are folded into one tool because they take the same argument and are all reversible; refusing to disable the current theme is an addition, the UI code does not check it. `Permissions.ApplyTheme` is declared in the module assembly and is the only permission the UI checks, including for enable and disable (the feature tools check `ManageFeatures` for other features). Switching the site theme is reversible but changes the whole public site at once; whether that deserves approval is an open question.

## Indexing — `OrchardCore.Indexing`, `OrchardCore.Indexing.Worker`

**What an admin can do in the UI:**

- **Search → Indexes** (`ManageIndexes`): list and search index profiles of every provider; create one by choosing a provider and source type (for example "Content in Lucene", "Content in Elasticsearch", "Content in Azure AI Search"); edit (display name; for the `Content` type: indexed content types, culture, index latest or published; provider part: analyzer, store source data, default search fields, query analyzer, allow Lucene query syntax or Elasticsearch search type); **Synchronize**, **Reset**, **Rebuild**, **Delete** (with force) per row and as bulk actions.
- `OrchardCore.Indexing.Worker` only adds the "Indexes Content Updater" background task (every minute).
- One dynamic permission `QueryIndex_{name}` per index profile (granted in Roles).

**Already covered:** recipe steps `CreateOrUpdateIndexProfile`, `ResetIndex`, `RebuildIndex` (usable through `importOrchardCoreRecipe`). Listing, reading, synchronizing and deleting are not covered. Which parts and fields of a content type are included in an index (`LuceneContentIndexSettings`, `ElasticContentIndexSettings`, `AzureAISearchContentIndexSettings` on type-parts and part-fields) are content definition settings, already reachable with `applyContentTypeDefinitionFromRecipe`.

| `saveQuery` | Security | yes | `ManageQueries`, and also `ManageSqlQueries` when the source is Sql | Creates or updates a saved query: name, source, template (a SQL SELECT or a JSON search query, Liquid allowed), index for search sources, optional result schema and the return-content-items flag. | `runQuery` | Read | no | `ExecuteApi_{name}` (`QueryPermissions.CreatePermissionForQuery(name)`, implied by `ExecuteApiAll` and `ManageQueries`) | Executes a saved query by name with optional parameters and returns its rows or content items. **Implementation notes:**

- Services: `IQueryManager` (`ListQueriesAsync`, `PageQueriesAsync`, `GetQueryAsync`, `NewAsync(source, JsonNode data)`, `UpdateAsync(query, data)`, `SaveAsync`, `DeleteQueryAsync`, `ExecuteQueryAsync(query, parameters)`) in `OrchardCore.Queries.Abstractions`; `IQuerySource` services give the enabled sources. The data shape for every source is `{ Name, Source, Schema, ReturnContentItems, Template, Index }` (`SqlQueryHandler`, `LuceneQueryHandler`, `ElasticsearchQueryHandler` read `Template` and `Index` from the data).
- Validation only in display drivers, to repeat: name required and equal to `ToSafeName()`, unique name, schema must be JSON (`QueryDisplayDriver`); template required, index required for search sources; for Sql, `SqlParser.Validate` when the template has no Liquid, and a warning when it has Liquid output expressions (`SqlLiquidOutputExpressionDetector`). Edit with a new name is delete then update.
- SQL is SELECT-only: `SqlParser` rejects anything else ("Only SELECT statements are supported.") and rewrites table names with the tenant prefix. It is still a raw read of the tenant database: the `Document` table holds user records with password hashes, site settings and other modules' data, and no content permission applies. `ManageSqlQueries` is flagged `isSecurityCritical`, and the default Editor role has it. Hence Security with approval, a forced row limit, and no other tool that can run unreviewed SQL without approval.
- That is also why `saveQuery` is Security with approval for every source: otherwise the model could save a Sql query and run it through `runQuery` without approval. The UI lets a user with only `ManageQueries` save a Sql query; the tool is stricter on purpose.
- `runSqlQuery` without a module reference: `IQueryManager.NewAsync("Sql", data with Template)` then `ExecuteQueryAsync`. Drawback: `SqlQuerySource` logs parse errors and returns an empty result. To return parse errors and the generated SQL like the admin page does, the tool needs `SqlParser` (public class, `Validate` is internal) from the `OrchardCore.Queries` module assembly.
- `runQuery` should cap the number of returned rows and the size of each row.

## Open questions

- Module-assembly dependency. `CrestApps.OrchardCore.AI.Agent` references only abstractions and core packages and mirrors Orchard permissions in `OrchardCorePermissions` to avoid module references, and the repository rule in `CrestApps.OrchardCore/CLAUDE.md` says module code never uses a type from another module assembly. In this group these services and models exist only inside module assemblies: `TemplatesManager`, `AdminTemplatesManager`, `Template` (OrchardCore.Templates); `PlacementsManager` (OrchardCore.Placements); `ShortcodeTemplatesManager`, `ShortcodeTemplate` (OrchardCore.Shortcodes); `MediaProfilesManager`, `MediaProfile`, `MediaDirectoryTreeCache`, `AttachedMediaFieldFileService` (OrchardCore.Media); `ISiteThemeService` (OrchardCore.Themes); `SqlParser` (OrchardCore.Queries). So 16 of the 40 tools need a decision (the 4 template, 3 placement, 2 shortcode-template, 3 media-profile and 2 theme tools, and the 2 folder tools for the tree-cache invalidation), and two more are limited without it (`listShortcodes` cannot return template content, `runSqlQuery` cannot return parse errors): reference the module packages (against that rule), resolve by reflection, implement saves through the recipe steps (which leaves list, get and delete without a route), or get the managers moved to core libraries upstream in Orchard Core. Permissions declared in module assemblies and therefore to be mirrored by name: `ManageTemplates`, `ManageAdminTemplates`, `ManagePlacements`, `ApplyTheme`, `ViewAmazonS3MediaOptions`, `ViewAzureMediaOptions`.
- `importOrchardCoreRecipe` bypasses the per-area checks proposed here: with one permission (`ManageRecipes`) and one approval it can run `media` (any URL, overwrite, restricted extensions), `Templates`, `AdminTemplates`, `ShortcodeTemplates`, `Queries` (including Sql) and `Themes`. Should that tool refuse or separately confirm these step names once dedicated tools exist?
- Approval for high-impact but reversible writes. By the brief's rule `setTheme`, `savePlacement`, `saveIndexProfile`, `synchronizeIndexProfile` and `purgeMediaCache` are Write without approval. `setTheme` changes the whole public site at once, and for Elasticsearch and Azure AI Search `saveIndexProfile` and `rebuildIndexProfile` call an external (possibly billed) service. Should any of these be raised to approval?
- `runSqlQuery` is classified Security with approval although it only reads, because it bypasses every content and user permission and can return password hashes and stored settings. Confirm that classification, and decide whether the tool should also refuse some tables or columns, and what the row limit is.
- `saveQuery` requires approval for all sources to close the "save a Sql query, then run it with `runQuery`" path. The alternative is a no-approval `saveQuery` limited to search sources plus a separate approved `saveSqlQuery`.
- `saveMediaTextFile` is Security with approval because, with the default options, the text extensions it can write are mostly the restricted ones (`.css`, `.js`, `.svg`). The alternative is a no-approval tool that refuses restricted extensions, which with defaults would only write `.csv`.
- Uploading a file the user attaches in the chat is the main Media UI action and is not covered: it needs the chat attachment (binary) to be reachable from a tool. Is there a mechanism for that (for example the AI documents feature), so a `saveMediaFileFromAttachment` tool can be added?
- A `renderLiquid` (or template preview) tool would let the model test a template against a content item before `saveTemplate`, as the UI preview does. Rendering arbitrary Liquid on the server reads data without permission checks, so it would be Security with approval. Wanted?
- Default role grants make the Security tools reachable by Editors: the default Editor stereotype has `ManageTemplates`, `ManageLiquidTemplates`, `ManageShortcodeTemplates`, `ManageQueries`, `ManageSqlQueries` and `UploadRestrictedMedia`. Is approval enough, or should these tools be limited to profiles used by administrators?
- `ManageAzureAISearchSettings` is not returned by any permission provider in this checkout, while the menu entry uses `ManageIndexes`. Which permission should the generic settings tool check for group `azureAISearch`?
- The existing tools read (for example `DisableFeatureTool`) do not call `IAuthorizationService` for the Orchard permission inside the tool; access is gated per tool by `AIPermissions.AccessAITool`. The Permission column above assumes each new tool checks the listed permission for the calling user, and for media with the path as resource. Confirm that this is the intended pattern (unverified for all existing tools).
- Read tools that other agents need: `listMediaFiles`, `getMediaFile`, `listMediaProfiles` and `listShortcodes` are needed by ContentAgent to fill media fields and write bodies. Should they be listed on both agents, or ticked directly on the main assistant?

# 11 - Forward review: from the Orchard Core features to the framework, without regression

This review walks every Orchard feature in scope, states what it does today, what its `Startup` looks like after Phase 0/1, what must stay identical, and which tests and checks pin it. [Appendix C](appendix-c-startup-registration-inventory.md) is the line-by-line registration list behind each row; this document is the feature-level regression checklist. Use it as the acceptance script for the Phase 0 and Phase 1 manual reviews.

## 2. Cross-feature flows to re-verify manually at each gate

1. Inbound call: Telnyx webhook -> provider inbox -> voice ingress -> entry point -> queue -> offer on the hub -> accept in soft phone -> connected -> hold/transfer -> hangup -> wrap-up -> disposition -> interaction/event log -> metrics.
2. Outbound preview dial from a campaign batch with DNC screening, agent bridge, recording, and secure pause.
3. Direct-to-agent entry point ringing one user, voicemail on no-answer, voicemail playback.
4. Extension-to-extension call between two registered agents.
5. Supervisor monitor/whisper/barge on a live call.
6. Inbound SMS -> portal inbox (number route, then routed queue), reply, template, broadcast, quiet-hours block, keyword opt-out.
7. AI SMS automation with cadence re-engagement, after-hours gating, and handoff to a queue.
8. Automated voice call (turn-based and realtime) with escalation and conclusion.
9. Agent presence lifecycle: sign in, break with reason code, after-call recovery, logout revokes credentials and signs out of queues.
10. Tenant setup from the Contact Center recipe, deployment export/import of queues/skills/entry points/dialer profiles/business hours/reason codes, workflow event triggers.
11. Feature enable/disable sequences from `ContactCenterFeatureActivationTests` (each capability enabled alone, then with dependents).
12. Two-node run (DistributedTests) for backplane, rendezvous, and lock behaviour.

## 3. Things easy to miss (checked explicitly)

- `EnabledByDependencyOnly` features (`AgentServices`, `ChannelEndpoints`, `ProviderInbox`, `Voice`, `Voice.Media`, `Recording.Core`, `RealTime`, `SoftPhone.Core`, `WebSockets`, `PhoneNumbers`) keep their flag; the framework has no equivalent, so their registrations must be reachable from the dependent features' `AddCore*` methods too.
- `[RequireFeatures]` startups (deployment, recipes, workflows, health checks, Redis, Reports, AI subject flow, Content Transfer, DNC + Content Transfer, Contents, Telnyx/Asterisk/Dialpad with CC Voice/Media, Telnyx AiVoice) keep their conditions; only their framework-eligible lines move.
- Startup ordering rules that today rely on `TryAdd` (Telnyx inbound router) become explicit `Replace` inside the framework method.
- `services.Configure<MvcOptions>` filters (soft phone widget/extension dialer filters, agent bar filter) stay Orchard.
- `IContentDefinitionEventHandler` / `OmnichannelContentTypeProvider` singletons stay Orchard.
- `Lazy<T>` registrations (`Lazy<IProviderCallStateSynchronizationService>`, `Lazy<ISmsConversationAuthorizationService>`, `Lazy<IAuthorizationService>`) are kept in the framework methods.
- The Asterisk web host (`CrestApps.OrchardCore.Asterisk.Web`) and Aspire hosts keep building.
- Resource manifests keep serving the module `wwwroot` bundles until Phase 2 switches to the resources package.
- `InternalsVisibleTo` for `DynamicProxyGenAssembly2` (Moq) and the distributed tests move with the assemblies.
